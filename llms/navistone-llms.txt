# NaviStone

> NaviStone is a direct-mail marketing technology company that turns first-party and "unknown" website audiences into addressable postcard campaigns for consumer brands. Its platform API manages clients, website domains, audience segments, campaigns (linked to Modern Postcard creative IDs), ZIP/state geo-targeting, and mail output tracking, secured with an X-API-Key header.

## APIs

- [NaviStone Platform API (Swagger UI)](https://docs.navistone.com): The entire published developer surface — a static Swagger UI, no prose reference, no getting-started guide.
- [OpenAPI (JSON)](https://docs.navistone.com/openapi.json): Machine-readable OpenAPI 3.0.0 definition, 36 operations across API Info, Campaigns, Clients, Domains, Geo Targeting, Health, Output and Segments.

## Calling notes

- Authentication is an `X-API-Key` request header on 33 of the 36 operations; the three `/api/health*` probes are unauthenticated.
- The OpenAPI declares no `servers[]`, so the contract names no host. `docs.navistone.com` is a static S3 bucket (403 on `/api/*`) and `api.navistone.com` is a Kong gateway with no publicly exposed route, so the runtime base URL is not discoverable from anything NaviStone publishes. Obtain it with your API key from NaviStone.
- No idempotency key, no rate-limit headers, no 429 response, no request-id header, and no versioning or deprecation policy are documented.
- Errors are NestJS-shaped `{ statusCode, message, error }` JSON, not RFC 9457 problem details.
- Deletes are soft (`active=false`) for clients, campaigns, domains and segments; `DELETE /api/output/{id}` is the one hard delete.
- Only the clients list declares `page`/`limit` pagination; other list operations are unbounded.
